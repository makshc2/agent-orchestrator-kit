## Why

Live-спостереження 2026-09-07 за consumer-зміною `fix-location-search-filter-cascade` (vms-ext-frontend, kit 0.13.0, 8 сесій: Cursor → Amp → Claude → Amp → Claude → Amp → Claude → Claude) показало, що `metrics.json` арифметично консистентний, але його вхідні дані хибні: один persist без restore записав сесію з `startedAt 2026-06-06`, 2002 Amp-sources з 74 старих тредів, 163.6M токенів і повторно просумував `$19.77` уже оплачених тредів (`spend.costUsd` 11.25 → 31.02, work time 2243h, файл 849 KB / 27 163 рядків); Claude-адаптер рахує кожен streamed-рядок jsonl окремо (×2.5–2.7 токенів у кожній Claude-сесії), не читає subagent-транскрипти (`<sessionId>/subagents/agent-*.jsonl`, 879k токенів spec-reviewer), відкидає рядки після `cd` у підпапку проєкту, а leftover без thread-фільтра приріс 17 хвилин хотфіксу поза OpenSpec до apply-сесії (1.4M → 16.3M). Amp leftover тримає застарілий Cost (2.85 при usage `$3.96`), Amp-токени дорівнюють 32–40% usage-таблиці. Журнал має стати правдивим рахунком change-у і компактним git-tracked файлом.

Design: `design.md` (нова компактна схема сесії v2 + міграція).

## What Changes

- **SESSION-V2-COMPACT.** Запис сесії SHALL зберігати агрегати плюс `sourceIds` (для dedup) і `byModel` (per-model токени / cost / estimate), а не масив `sources[]` per-message об'єктів. `version` файла стає `2`; v1-файли читаються і мігруються на першому реальному записі (`sources` → `sourceIds` + `byModel`). Конвертація схеми точно зберігає всі наявні числові поля сесій і top-level `spend`/`totals`/`spendByPlatform`/`spendByModel`/`phases`, без числового backfill або recompute; звичайне read-only відображення v1 не пише файл. Наступні реальні записи перераховують агрегати зі звичайних session-level полів і `session.byModel`. Cursor upgrade того самого id (кумулятивні totals) підтримується через `sourceTotals` (`id → totalTokens`).
- **PERSIST-NO-PENDING-WINDOW.** Persist / archive без `pending` і без `--started-at` MUST NOT збирати з відкритою нижньою межею: нижня межа = `endedAt` останньої закритої сесії (або `createdAt` файла, якщо сесій немає). Amp collect у persist MUST NOT викликати `listRecentAmpThreadIds`; без thread id локальні `threads/*.json` MUST NOT скануватись. Cost треда, який уже billed у попередній сесії, MUST NOT додаватись повторно (thread-level dedup за id). Stderr warning «persist without restore».
- **CLAUDE-DEDUP-SUBAGENTS-CWD.** Claude-адаптер SHALL дедуплікувати рядки за `message.id` у межах проходу (лишити запис з найбільшим `totalTokens`), читати `<projectDir>/<sessionId>/subagents/*.jsonl` і `<projectDir>/agent-*.jsonl`, а cwd-match робити за префіксом (`row.cwd === root` або `row.cwd.startsWith(root + sep)`).
- **THREAD-ID-AND-LEFTOVER-CAP.** Cursor persist без pending SHALL записувати env `CURSOR_CONVERSATION_ID` у `session.threadId` (той самий id, що використано як фільтр). Для сесій з `threadId: null` leftoverEnd SHALL бути `min(next pending.startedAt, endedAt + 120s)`; правило «до pending.startedAt навіть пізніше за 120s» лишається лише для сесій з непорожнім thread id.
- **PRE-RESTORE-GRACE.** Вікно persist / archive для locked client SHALL починатись з `pending.startedAt − 120s` (dedup за id проти всіх сесій), щоб status/restore-ходи чату і хід Archiver не губились.
- **AMP-USAGE-TRUTH.** Коли `amp threads usage --details` доступний, session-level `inputTokens`/`outputTokens` Amp-сесії SHALL братись з рядків `Input tokens` / `Output tokens` usage (включно з helper-моделями Sol/Luna/Terra), `byModel` — з таблиці Models; `session.model` — модель чату з export-повідомлень (найбільше токенів серед `usage.model`), не display-ім'я helper-моделі. Leftover SHALL оновлювати `session.costUsd` свіжим `Cost: $N`, коли usage його віддав; `priorCost` лишається лише коли usage недоступний.
- **ESTIMATE-ALL.** Кожна сесія і кожен рядок `byModel` без billed USD SHALL отримувати `costUsdEstimated` з токенів: Claude — версійована таблиця Anthropic list-price у `bin/claude-cost-estimate.js` (input / cache read / cache write / output за MTok для `claude-fable-5*`, `claude-opus-*`, `claude-sonnet-*`, `claude-haiku-*`; невідома Claude-модель → fallback $3 / $15 як у Cursor), `costSource: api-estimate`; Amp без рядка `Cost: $N` — та сама таблиця за нормалізованим ім'ям моделі (Claude-моделі) або fallback $3 / $15 для решти, `costSource: api-estimate-fallback`; Cursor — без змін. Estimate MUST NOT потрапляти в `costUsd`; human summary і далі друкує `$X billed + ~$Y est.` для кожної фази/платформи/моделі, тож у change-у без billed видно приблизну вартість.
- **PHASE-BOUNDS-EXPORT.** Зовнішній дашборд «agent factory metric» показує для spec / review / apply / усього однакові межі 18:56–19:24 і 27 хв 59 с, бо бере час із git-комітів change-у, а не з `phases.<phase>`. Kit SHALL віддавати стабільний контракт для дашбордів: `metrics <name> --json` (v2) містить `phases.<phase>.{ sessions, startedAt, endedAt, durationMs, leadTimeMs, inputTokens, outputTokens, totalTokens, costUsd, costUsdEstimated, agents, models }` і `totals`; новий `metrics <name> --summary-json` друкує лише `{ version, change, createdAt, archivedAt, totals, phases, spend, spendByPlatform, spendByModel }` без сесій; README «Change metrics» отримує розділ «Для дашбордів»: межі й тривалість фази беруться лише з `phases.<phase>`, `totals.leadTimeMs` — лише для «Усього», git log MUST NOT використовуватись для меж фаз, per-phase лічильник комітів kit не постачає (це випливає з вимоги change-metrics «Межі фази — з сесій цієї фази, не клон totals»).
- **SPAWN-NAME.** `firstSpawnName` SHALL брати ім'я субагента лише з backtick-токена або з карти канонічна роль → субагент; вільний текст Next role MUST NOT давати ім'я (`baseline` з «усунення baseline lint»).
- **RULE-TEXT.** `session-handoff.mdc` (kit + templates): перегенерація промпта — лише `--no-metrics`; повний persist повторно MUST NOT запускатись; `decisions.md` пише лише CLI; після persist чат зупиняється, хотфікс поза OpenSpec — новий чат; Amp/Claude агент MUST заповнити `platform` і `model` у `## Metrics` (не `unknown`).
- Без HTTP, без Amp billing API, без Cursor SDK, без нових npm-залежностей, без бекфілу вже заархівованих consumer-файлів (окрім документованого `metrics <name> --migrate`, який лише переписує схему). Grace 120s не змінюється. Cursor estimate table не змінюється; ставки Claude — статична версійована таблиця без HTTP.

## Non-goals

- Бекфіл консюмерських архівів понад `--migrate` схеми (числа не перераховуються з диска).
- Claude `sessionId` як `threadId` і фільтр за ним (немає надійного env; окрема зміна).
- Точний старт першої сесії change-у до появи `handoff.md` (restore без файла лишається exit 1; окрема зміна `restore --new`).

- Точна вартість Claude Code підписки / Amp credits → USD (лише list-price estimate).

## Acceptance criteria

Кожен критерій відповідає бойовому спостереженню; перевіряється через CLI / `metrics.json`.

1. **Persist без pending не підмітає історію.** `metrics.json` з 6 сесіями (остання `endedAt` T), `pending: null`, без `--started-at`; у `AMP_DATA_DIR/threads` 74 треди з `trees` цього cwd за червень; `## Metrics platform: amp` → нова сесія має `startedAt === T`, `sourceIds` без жодного id з датою < T, `listRecentAmpThreadIds` не викликається, `spend.costUsd` не зростає на Cost тредів, уже присутніх у `sessions[*].threadId`. Файл < 100 KB.
2. **Claude dedup за message.id.** Jsonl з 15 рядками на 6 `message.id` (однаковий usage) у вікні → `sourceIds.length === 6`, `inputTokens === 359148` (сума 6 унікальних), не `906419`.
3. **Claude subagents і cwd-префікс.** `<projectDir>/<sid>/subagents/agent-a.jsonl` з 15 msg у вікні та рядок батька з `cwd = <root>/openspec/changes/x` → усі входять у `sourceIds`; рядок з `cwd = /other/project` не входить.
4. **Leftover cap для threadId null.** Закрита Claude-сесія `endedAt` E, `threadId: null`, наступний `pending.startedAt = E + 17m`; рядки на E+30s і E+6m → перший причеплено, другий ні. Та сама сесія з `threadId: X` і рядками `conversationId X` — обидва причеплено (старе правило).
5. **Cursor threadId без pending.** Persist без pending з `CURSOR_CONVERSATION_ID=c39e…` → `sessions[n].threadId === 'c39e…'`; leftover наступного persist фільтрує за ним.
6. **Pre-restore grace.** `pending.startedAt` P, рядок на P−40s з тим самим клієнтом і id, якого немає в попередніх сесіях → входить у нову сесію; рядок, уже причеплений leftover-ом попередньої сесії, не дублюється.
7. **Amp usage — правда.** usage віддає `Input tokens: 1,320,187`, `Output tokens: 17,353`, `Cost: $3.96`, Models Astra/Sol/Luna; export має 13 повідомлень gpt-6-astra → `session.inputTokens === 1320187`, `session.costUsd === 3.96`, `session.model === 'gpt-6-astra'`, `byModel` три рядки, `sourceIds.length === 13`. Після leftover з usage `Cost: $2.51` (було 1.91) → `session.costUsd === 2.51`.
8. **v2 схема і міграція.** Persist на v1-файлі з `sessions[0].sources` (4 записи) → файл `version: 2`, `sessions[0].sourceIds.length === 4`, `sessions[0].byModel` з тими самими токенами, ключа `sources` немає; агрегати не змінились. `metrics <name> --json` на v1-архіві без запису повертає мігрований об'єкт, файл на диску не змінюється; `metrics <name> --migrate` переписує файл.
9. **Cursor upgrade того самого id.** Leftover бачить hook-рядок з відомим id і більшим `totalTokens` → `sourceTotals[id]` і session totals оновлені, `sourceIds` без дубля.
10. **Spawn name.** Next role `Implementer — відновити verification після усунення baseline lint` → prompt містить `subagent-<phase-specialist>` / карту ролей, не `subagent-baseline`; Next role `Architect (spawn \`spec-architect\`)` → `spec-architect`.
11. **Rule text.** Канонічний `templates/.agents/rules/session-handoff.mdc` і компактне kit-правило містять: `--no-metrics` для перегенерації промпта, заборону повторного повного persist, «decisions.md пише лише CLI», «після persist — новий чат, хотфікс поза OpenSpec — новий чат», обов'язкові `platform` і `model`; template зберігає наявні `git-tracked` / `Runtime` / `cloud-check` перевірки, а сума template-правил з `alwaysApply` лишається < 12000 символів.
12. **Estimate для Claude і Amp без Cost.** Claude-сесія `claude-opus-5` з `input_tokens 100000`, `cache_read 900000`, `cache_creation 0`, `output 10000` → `session.costUsdEstimated === 1.2` (100k×$5 + 900k×$0.5 + 10k×$25 за MTok), `costUsd === null`, `spendByPlatform.claude.costUsdEstimated === 1.2`; Amp-сесія без рядка `Cost:` з моделлю `gpt-6-astra` 1M in / 10k out → `costUsdEstimated === 3.15` (`api-estimate-fallback`), `costUsd === null`; human summary для review показує `~$1.20 est.`, не `—`.
13. **Дашборд бере межі фаз із phases, не з git.** На файлі з сесіями spec (15:17–15:31, dur 539356) і review (15:26–15:39, dur 459267) `metrics <name> --summary-json` друкує `phases.spec.startedAt !== phases.review.startedAt`, `phases.spec.durationMs === 539356`, `phases.review.durationMs === 459267`, `totals.leadTimeMs` = earliest→latest по всіх сесіях; вивід не містить ключа `commits`; README містить розділ «Для дашбордів» з реченням, що git log MUST NOT використовуватись для меж фаз.
