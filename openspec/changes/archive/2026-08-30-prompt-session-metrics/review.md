## New findings

### Medium (non-blocking)

**M-A — the archive final-handoff rewrite will wipe `## Metrics`, and task 4.5 does not pin the read order.**
`bin/agent-orchestrator.js:3239-3258`: after the move, `archive` builds a fresh `fields` object and calls `writeFileSync(join(targetDir, 'handoff.md'), buildHandoffMarkdown(fields))`. That object carries `runtime` and `agentId` forward from `priorFields` (3237, 3252) but has no `metrics` key. Once task 1.1 lands, `buildHandoffMarkdown` renders `unknown` for every missing value, so the archived `handoff.md` loses the agent's self-report in the same command that reads it. Two consequences: (a) the archived artifact no longer shows what was reported, which sits against the design premise that `handoff.md` is the record of what the agent declared; (b) task 4.5 says only «у гілці archive після move … прочитати `## Metrics`» — line 3258 is also "after move", so an implementer who places the read after the rewrite will silently resolve the Archiver session to `null` and break scenario `Archiver бере значення з самозвіту` (change-metrics 539) and criterion 9. Task 4.5's Done-when does catch (b) if it is actually exercised; nothing catches (a). Resolution: carry `priorFields.metrics` into the archive `fields` object and state the ordering in task 4.5's `Do:`. Carried into `apply-notes.md`.

**M-B — `parseMetricsSection` warnings have no consumer.**
`specs/change-metrics/spec.md:7` requires that an unparsable number «SHALL давати `null` і warning у stderr». Task 1.2 (`tasks.md:11`) puts those messages into a returned `warnings` array and task 1.3 adds the invalid-platform message to the same array, but no task prints `fields.metrics.warnings`. Only the platform warning has a real owner, via `resolvePlatform` (task 2.2) and the existing `console.error(platformResult.warn)` at `bin/agent-orchestrator.js:3620`; the numeric warnings would be collected and dropped. The observable behaviour is fully specified (stderr, warn-only, exit 0) so this is a wiring gap rather than a guess about intent. Resolution: name the print site in task 1.2 or 2.5. Carried into `apply-notes.md`.

### Low (non-blocking)

**L1 — criterion 9 and scenario `Archiver бере значення з самозвіту` have no test task.** §6 covers the parser (6.1), persist chains (6.2), aggregates and archive tables (6.3), the removed hook self-heal (6.4) and the `--no-collect` rewrites (6.5), but nothing asserts that the Archiver session picks up `platform` / `model` / tokens from the archived `handoff.md`. Combined with M-A this is the least-protected path in the change.

**L2 — an anti-regression clause disappears from `openspec/specs/` after sync.** Both main specs currently carry the parenthetical «Amp credits і заповнені токени не скасовують warning; не перевіряти `sessions.length === 0` і не перевіряти всі `METRICS_SPEND_KEYS`» (`openspec/specs/change-metrics/spec.md:357`, `openspec/specs/lean-archive/spec.md:47`). The `change-metrics` MODIFIED replacement (delta 531) keeps the warning but drops the parenthetical, and the `lean-archive` copy is removed, so after sync the guard exists nowhere. The behaviour is unchanged by this change and `warnMissingUsd` (`bin/agent-orchestrator.js:1925`) already implements it, but the clause was written to stop a specific regression.

**L3 — the `total_tokens` sum sentence still sits in the parser requirement.** `specs/change-metrics/spec.md:7` says «Якщо `total_tokens` відсутній, але є `input_tokens` або `output_tokens` — `total_tokens` SHALL дорівнювати сумі наявних» inside the requirement that describes section parsing and normalization, while tasks 1.2 / 2.3 and decision `total-tokens-single-owner` place the sum exclusively in `resolveSessionSpend`. The sentence is observable-behaviour-shaped so the tasks disambiguate it, but its placement is the same invitation to double-apply the decision was written to remove.

**L4 — legacy default: schema requirement says merge, task says display layer.** The MODIFIED `metrics.json` requirement (delta 285) states that legacy files merge missing fields with defaults including `spendSource: "unreported"` and `ampCredits: null`, while task 4.3 says `loadMetricsFile` does not normalize session records at all. The observable scenario (`Legacy сесія без spendSource читається як unreported`) passes with a display-layer default, but `session.ampCredits` stays `undefined` rather than `null` on legacy records.

**L5 — task 5.1's Done-when is half-vacuous.** «не містить рядка `--no-collect`» is already true: `templates/.agents/rules/session-handoff.mdc` never mentioned the flag. The real edit named in the `Do:` is removing the auto-collect sentence ("Persist … local usage from Claude JSONL, Amp threads, and the Cursor spend hook file"), which also appears in `templates/.agents/subagents/session-handoff.md` and is what task 5.2 must remove. The Done-when does not verify it.

**L6 — criterion 8 asserts character-for-character equality with no scenario behind it.** `proposal.md:57` requires the `archive` summary block to match `metrics <name>` output exactly; the delta requires only that both render through the same function. Shared rendering makes it achievable (task 4.2 has `renderMetricsSummary` return an array of lines, and task 4.4 prints it after the existing `change/schema/archive/sync/handoff/memory/metrics` lines, which exist at `bin/agent-orchestrator.js:3269-3275`), but nothing tests it.

**L7 — `decisions.md` doubled date prefix is cosmetic.** Lines 24-28 carry `- 2026-08-30 2026-08-30 …`; five of them are English restatements of four earlier Ukrainian entries plus one new (`architect-fix-round-scope`). The doubling comes from `handoff.md ## Decisions` entries already carrying a date before the CLI prepends its own, and the append-only dedup compares normalized text, so the differently-worded duplicates were appended rather than merged. Content agrees with the Ukrainian originals in every case — no decision contradicts another, and no artifact depends on the prefix. Not a spec inconsistency; worth cleaning up in a future handoff-authoring pass, not in this change.
