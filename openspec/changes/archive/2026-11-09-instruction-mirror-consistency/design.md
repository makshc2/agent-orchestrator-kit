## Goals / Non-Goals

**Goals:**
- One source per mirrored text; no drift after the kit CLI commands `init`, `update` and `sync` (the shell script `scripts/sync-local-agent-skills.sh` only copies files and does not regenerate blocks, so the README tells to use the CLI), and drift in the kit's own templates caught by a test.
- Specialists read their own steps from their own file.
- Remove instruction rules that contradict recorded data.
- No new contradiction between a main spec and a template: every text a task removes or moves is either re-homed or covered by a delta (see D4, D7, D8 and the re-scan table in D9).

**Non-Goals:**
- Mirrors in `subagents/session-handoff.md` and `spec-archiver.md` (own voice, pinned step counts: 4 restore, 6 persist), `CLAUDE.md` `@`-include, `memory-mcp-autosetup.mdc`, moving `openspec-howto`/`spec-workflow-openspec` (see proposal Non-goals for follow-up names).

## Decisions

**D1. Marker blocks inside `SKILL.md`, generator as a pure module.** Block syntax: begin line `<!-- aok:mirror:begin <id> (generated from <source>; edit the source and run sync) -->`, end line `<!-- aok:mirror:end <id> -->`. `bin/instruction-mirrors.js` exports `MIRROR_TARGET`, `MIRRORS`, `extractMirrorSource(text, spec)` and `syncInstructionMirrors(root, { check })`; `root` is a directory that contains `.agents/` (a project, or `templates/` in the kit). It returns `{ changed: string[], drift: string[], skipped: string[] }`; with `check: true` it writes nothing. Alternative considered: a build script writing templates only. Rejected because a consumer who updates a rule would otherwise get a stale skill until the next kit release; running in `init`/`update`/`sync` fixes it locally. A skill without markers (a project installed before this change) is skipped, and the CLI warning names `update` as the remedy, because `update` reinstalls the kit skill with the markers.

**D2. Source extraction by heading, not by line number.** `session-start`: lines after the heading line starting `## Session Start` up to the next line starting `## `. `session-exit`: same with `## Session Exit`. `routing`: from the line starting `The parent \`/opsx:*\` session is the **conductor**.` in `agent-orchestration.mdc` up to the next line starting `## `. Leading and trailing blank lines are trimmed. A missing heading means the block is skipped (reported in `skipped`), never emptied.

**D3. Skill layout after the edit.** `## Conductor Routing` keeps its heading, then the `routing` block, then the existing paragraph beginning "`spec-reviewer` is not `code-reviewer`" (extended escape-valve text, not in the rule). `## Session Rules` keeps `**Start of each session:**` + `session-start` block, `**During session:**` bullets, `**End of each session (HARD STOP — you are NOT done):**` + `session-exit` block, then the `handoff.md` template (its `## Runtime` section is a test pin). The two paragraphs of "Mandatory Memory and Handoff Protocol" are replaced by one short paragraph (D4 lists what it keeps); the Entity table stays.

The generic pins `git-tracked` (smoke test) and `cloud-check` would still pass through the mirror blocks (Session Start item 2 mentions "git-tracked `openspec/changes/<name>/decisions.md`", Session Exit step 7 has `cloud-check`), but that would mask the loss of statement (1); therefore test 4.2 asserts both statements as full sentences on the skill text with the mirror blocks removed. **D5. Step moves are text moves.** `spec-architect.md` gets the build loop as an unnumbered paragraph block after workflow item 6 (the numbering is referenced by "the one exception to workflow step 6" in its Rules). The loop keeps every instruction of the removed text: `new change`, `status --json` fields, `instructions` fields including `instruction` (schema-specific guidance), template/context/rules handling, the "never copy `<context>`/`<rules>` blocks into the file" rule and the stop-and-report branch for an artifact that needs user input (a subagent cannot ask the user, so it returns `Status: blocked` per its Rules). `opsx-propose.md` and `openspec-propose/SKILL.md` drop steps 3–5 and the "Artifact Creation Guidelines" section and renumber the final verification step to 3; the Thin conductor paragraph, the Tier 1 pre-gate text and the task contract stay byte-identical in both files (pinned). `design-intake.md` gets source ladder, capture, brief template and confidence markers (D7); `opsx-design.md` keeps selection, spawn, verify/handoff, exit and guardrails.

**D6. `code-reviewer` diff precondition.** Three probes, all restricted to `pipeline.src_glob` (read from `.agents/orchestrator.yaml`, default `src/`): `git diff HEAD --stat -- <glob>` (staged and unstaged changes; plain `git diff --stat` shows only unstaged changes and gives a false "no diff" for staged work), `git diff --stat <target-branch>...HEAD -- <glob>` (commits not yet in the target branch) and `git ls-files --others --exclude-standard -- <glob>` (new untracked files, which `git diff` never lists). All empty and no file named by the user means `Status: blocked` "no implementation diff". A comma-separated `src_glob` is split into separate pathspecs by the reviewer (the gate-check parser fix is a separate item of the plan).

Option B was to keep the ladder and template in `opsx-design.md` and drop the move. Rejected: the command forbids the parent to inspect the source or write the brief, so about 70 lines of it are instructions for the specialist sitting in the wrong file, and the specialist file stays without the template it is asked to produce; B would also leave half of item C of the plan undone. The scenario "Дозволені шляхи запису" stays true because `opsx-design.md` keeps its Guardrails, including "never rely on a second Figma MCP pass later". The other four requirements of the capability are untouched. No other pending change touches `design-intake`.

**D8. Positive trigger for optional and fallback agents.** The main requirement "Exclusive routing table in always-apply and commands" asks every subagent description for `ALWAYS use for` / `Use proactively`. `session-handoff` ("FALLBACK ONLY — use when ...") and `spec-archiver` ("Use ONLY when ...") already deviate, because the routing table marks them `fallback only`; `code-reviewer` is `optional` and its data (two runs without a diff) shows that an `ALWAYS` trigger is the defect. Rather than leave two contradicting texts, the delta MODIFIES that requirement (both scenarios kept): mandatory and on-signal agents keep the two literal triggers; fallback and optional agents (`session-handoff`, `spec-archiver`, `code-reviewer`) use a plain `Use ...` trigger with an explicit condition, and every description keeps a `Do NOT use` clause. The `Do NOT use for` wording of the main text is unchanged.

## Risks / Trade-offs

- Block markers are HTML comments inside a skill: harmless to agents, but a hand edit inside a block is overwritten by the next `sync`. The begin line says so.
- `openspec update` reinstalls `openspec-propose/SKILL.md`; the pointer edit holds only after the next kit `sync`/`update`. Until then the old steps coexist with the new specialist text, which agree.
- A legacy project whose skill has no markers prints a warning on every `sync` until `update` is run; the warning names `update`.
- Skill size shrinks slightly; the Claude/Amp protocol text is unchanged in meaning except for the two sentences it gains and the two small hand-written lines dropped on purpose (D4).
- README model hints name `ultra` for propose and review (D10); a reader who picks it pays the highest Amp rate. Reviewer downgrade is out of scope.
- Effect on review cycles is unproven (post-fix n=1); this change claims consistency, not speed.
