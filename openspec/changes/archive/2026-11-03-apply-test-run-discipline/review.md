### Minor

Not required before apply; fix opportunistically in a later propose or during apply with the owner's consent.

- **Exact-one-pending gap in the tests-line outcomes.** BLOCK-A, design Decision 5 and the apply-test-discipline requirement define `tests: not run (paused: <k> tasks pending)` only for "more than one task pending", while step 6.5 is entered only when the last task's Done-when holds. A session that ends with exactly one task pending and unfinished has no defined `tests:` line, although the requirement says every apply session ends with exactly one. The natural reading (`paused: 1 tasks pending`) is harmless; this is a convention, not a gate (Decision 6).
- **Normative wording in session-checkpoint "decisions stay in checkpoint.json".** The last sentence says the literal `none` "MUST be rejected as reserved by persist". It is `checkpoint` that rejects it (exit 1, task 4.1); persist silently drops it (existing `parseDecisionItems`). The scenario and tasks are correct, only the sentence misattributes. Same spec: the scenario titled "Handoff newer than checkpoint" (session-handoff delta) actually describes a checkpoint newer than `handoff.md`.
- **Recovered decisions rely on the next agent.** The UNKNOWN item is passive ("recorded when Session Exit persists ## Decisions") and may cut a long decision to 120 or 200 characters, while the full text lives only in `checkpoint.json`. Consider an imperative wording ("list it under ## Decisions at Session Exit; full text in checkpoint.json"). Unlisted decisions stay in `checkpoint.json` and, past 30, block further checkpoints (disclosed risk; deleting or replacing the file is the way out).
- **Small test-contract imprecisions (the implementer can settle them without design.md):** task 5.3 Done-when second fixture omits `handoff.md` (without it, or a Memory entity, restore takes the exit-1 early return, not exit 0); the narrowed pattern `opsx-archive` in task 3.2 matches no test name in `test/smoke.test.js` (the size check is still covered by `test/archive-from-terminal.test.js`); task 7.1 "the 31st call" means the call that adds the 31st decision; task 7.1 "old change ... identical output" may need path normalization between two temp directories; tasks 4.3 and 5.3 Done-when run the whole `test/smoke.test.js` without the narrowing escape that task 3.2 has (the project resource rule applies first).
- **Minor rendering edges:** BLOCK-D FACT 3 prints seq and savedAt for a superseded checkpoint while task 5.2 says such a checkpoint feeds only decisions and the GAPS item (metadata only, no forbidden field); the DETAILS line is not byte-capped for an unusually long change name (title name is cut to 60 bytes); no test asserts the 200-characters-per-line rule, only the 4096-byte and 40-line bounds; spec requirement 1 says "exit code MUST NOT change" while unreadable `handoff.md`/`decisions.md` (previously an uncaught crash) now degrade to exit 0 or the existing early-return 1 (requirement 6 states this precisely).
- **Split recommendation (groups 4–7 and the two Part B specs into `add-session-checkpoint`): note, not a blocker.** The artifacts stay inside both size budgets (margins 594 B and 2 637 B, no growth during apply because ticking a box keeps the byte count), the roadmap's one-phase-one-change rule is stretched but R5-lite is no factory phase, and the owner ordered the extension; conflict-table rows 1–2 stay PROPOSED for the owner. Practical cost: 14 of 20 tasks are Part B, and tasks 4.1, 5.1, 7.1 and 7.2 are far above the "~2 hours" guideline, so expect several apply sessions; groups 4–7 can be cut out as a unit if the owner prefers.
- **Unrelated drift (unchanged from the first cycle, out of scope):** README Role 4 still describes mandatory implementation specialists and 1–3 tasks per session; the setup-doctor template mentions cache checkpoints.
