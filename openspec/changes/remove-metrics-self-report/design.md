## Context

Session Exit currently asks the parent to fill a `## Metrics` section (`platform`, `model`, `input_tokens`, `output_tokens`, `cost_usd`, `amp_credits`, `spend_source`). `parseMetricsSection` reads it into `fields.metrics` (called `reported` in the persist and archive flows); `resolveModel`, `resolvePlatform` and `resolveSessionSpend` rank it between the flags and the adapters; `buildHandoffMarkdown` writes a skeleton back through `renderMetricsSection`; `warnUnreportedSelfReport` tells the agent to fill it; `sessionSpendIsFrozen` freezes a `self-report` session that has numbers; `dropStaleArchiveSelfReport` keeps the Archiver from re-counting the apply numbers.

Evidence (owner, 2026-10-01, re-counted when this change was proposed): 17 of 18 archived handoffs with the section hold only `unknown` (the 18th copies an Amp usage cost); `spendSource: self-report` in 0 of 94 sessions across 19 archived ledgers; `ampCredits` is `null` everywhere (the adapters emit `ampCredits: null`, and the CLI has no credits flag). The only live values are `flag` (none recorded), `amp-usage`, `adapter` and `unreported`.

Constraint: the decision `metrics-writeback-self-report-only` (2026-08-30) fixed that `handoff.md` is written before `metricsRecordSessionEnd`, so resolved numbers cannot be shown in `handoff.md` without a second write.

## Goals / Non-Goals

**Goals:** one source of truth (`metrics.json`); a shorter Session Exit; legacy `handoff.md` files still parse; one adjacent role fix with its own scenario and test.

**Non-Goals:** the list in `proposal.md` (`## Non-goals`). In particular: no schema change, no migration of archived files, no new warning, no change to `HANDOFF_REQUIRED_SECTIONS`.

## Decisions

**D1. Remove the section; do not rewrite it after resolution.** Alternatives: (a) a post-resolution rewrite of `handoff.md` with its own scenario, rejected: a second write, a second copy of data that already lives in `metrics.json`, and it reopens the 2026-08-30 ordering decision; (b) keep the section as an optional hint, rejected: it is the dead weight the evidence describes. `handoff.md` after persist is Closed role, Change, Done, Decisions, Blocked, Next command, Next role, Attach, Subagents to spawn, Constraints, Runtime, then `## Prompt`.

**D2. Legacy tolerance is behavior, not a kept parser.** `parseHandoffMarkdown` already turns any `## <title>` into an entry of the `sections` map, so a legacy `## Metrics` needs no code to be tolerated. `fieldsFromSections` stops reading it, `buildHandoffMarkdown` stops rendering it, so a rewrite drops it. `parseMetricsSection`, `renderMetricsSection` and their helpers (`normalizeMetricsBlank`, `parseMetricsNumber`, `formatMetricsField`, `METRICS_NULL_TOKENS`) are deleted, because a parser whose result nobody reads is dead code; the tolerance is pinned by the scenario "Legacy values are ignored" and its test. `HANDOFF_REQUIRED_SECTIONS` stays `Closed role`, `Done`, `Next command`, so 13-section handoffs from older kits still persist. `HANDOFF_SECTIONS` is dead code today; only its `'Metrics'` entry is removed.

**D3. The `reported` parameter disappears.** New shapes: `resolveModel(opts, env)` (adapter model, then `--model`, then `AOK_MODEL`, then `null`; the adapter step already lives in `applyCollectedSessionFields`), `resolvePlatform(opts, env, pending)` (flag, `AOK_PLATFORM`, `pending.platform`, host env), `resolveSessionSpend(opts, sources, extra)`, `applyCollectedSessionFields(session, sources, resolvedModel, opts, extra)`. `resolveSessionSpend` fills each field from the first non-null of flag, Amp usage, adapter sources; its `spendSource` is `flag` when any spend flag is set, else `amp-usage` when Amp usage gave `costUsd`, else `adapter` when any adapter number exists, else `unreported`. The `self.spendSource` and `self-report` branches are removed. `emptyMetricsFields`, `reportedHasSpendNumbers`, `dropStaleArchiveSelfReport` and `printMetricsSectionWarnings` go with their last caller. `resolvePlatform` and `resolveModel` are not exported, so only the `archive` and `handoff` action handlers and the `metricsRecordSessionEnd` / `metricsFinalizeArchive` call sites change.

**D4. Freeze means `flag` only.** `sessionSpendIsFrozen(session)` returns `session.spendSource === 'flag'`. Two call sites use it. `attachLeftoverSources` already has a compact-only branch for a frozen session (it grows `sourceIds`, `sourceTotals`, `byModel`, never the totals) and needs no change. `metricsBackfillFile` passed the frozen session itself as `reported` so that its totals and `spendSource` survived; with the parameter gone, the frozen branch passes the session's own `inputTokens`, `outputTokens`, `totalTokens`, `costUsd` and `ampCredits` as the `opts` argument, which `resolveSessionSpend` treats as flags and answers with the same totals and `spendSource: flag`. Accepted change: in the CLI leftover (`attachLeftoverSources`, `metrics --collect`) a stored legacy `self-report` session with numbers used to be frozen and is now resynced to the adapter totals when leftover arrives. No recorded session is affected (0 of 95 sessions in 20 ledgers); a consumer ledger that has one gets the adapter figure, which is the better source. The spec scenario "A stored self-report session is not frozen in the CLI leftover" and test 6 (`attachLeftoverSources`) pin it. `scripts/cursor-spend-collect.cjs` (and its byte-identical copy `templates/scripts/cursor-spend-collect.cjs`) is not edited and has its own rule: its live gate is `sessionSpendFrozen`, not `looksOverridden` (defined, never called). `sessionSpendFrozen` freezes `flag` (even without numbers) and any session that has spend numbers and a nonempty `spendSource` other than `adapter` or `unreported` (a missing or empty value is not frozen), so in the Cursor `sessionEnd` and hook-after-append leftover a stored `self-report` session with numbers stays frozen; its compact fields still grow. One rule, two owners: the CLI leftover freezes only on `flag`; the hook script keeps its own rule. The MODIFIED requirements say so consistently: the freeze paragraph is scoped to the CLI leftover, and both the collect-window and the empty-collect leftover requirements name the hook rule.

**D5. Warnings.** `warnUnreportedSelfReport` and its two calls (persist, archive) are deleted without a replacement; the plan lists the `fill ## Metrics` warning for removal and the evidence says it never recovered a number. Kept: `warnMissingModel` (it already names `--model` and `AOK_MODEL`), `warnMissingUsd` on archive, the ledger invariant warnings. The restore client label `unknown — pass --platform or fill ## Metrics` becomes `unknown — pass --platform`; the ADDED requirement "Restore names only --platform when the client is unknown" pins it. `--model`, `--platform` and the spend flags stay as the manual fallback for adapter gaps (Cursor).

**D6. Requirements left unchanged on purpose.** These name `self-report` or `## Metrics` only as one of several historic provenance values or in a condition that is now vacuous, and every sentence stays true: "Файл metrics.json є git-tracked журналом change-у", "Агрегати перераховуються на кожному записі", "Cursor spend hook — опційне доповнення, ensure лише в setup-командах", "Cursor estimate не змішується з billed USD", "--no-metrics пропускає запис сесії і collect", and the scenario "Leftover resync після двох sources" inside "Вікно collect". "Вікно collect, cwd-match і dedup" is still MODIFIED: one phrase would otherwise say that a numeric self-report is not rebuilt (it contradicts D4 for the CLI), and one clause names the Cursor hook script's own freeze rule. "Команда metrics показує ролі, моделі, платформи окремо" is MODIFIED for wording only: its scenario "Вивід показує unreported сесії" says "без самозвіту" and becomes "без зафіксованого spend", like the archive summary scenario; all its other text and scenarios are copied unchanged. Heading note: the spend-source requirement is RENAMED so its title no longer says "самозвіт"; other requirements cite it by the short name "Джерело spend", which still matches.

**D7. Canonical role.** `canonicalRole` gets `if (/^reviewer\b/i.test(value)) return 'Spec Reviewer';` next to the `spec reviewer` line. `Code Reviewer` does not start with `reviewer` and stays raw and flagged; `phaseForRole('Spec Reviewer')` already returns `review`. The scenario and test mirror the existing `Code Writer` pair. Side effect: `firstSpawnName` calls `canonicalRole`, so a `## Next role` of bare `Reviewer` now maps to the spawn name `spec-reviewer` (before: the empty string); it follows the existing canonical-role-to-subagent map and the rule that free text is never parsed beyond it, and no scenario pins it.

**D8. Text mirrors keep their step numbers.** In `session-handoff.mdc`, the skill and the `session-handoff` subagent, the "fill `## Metrics`" step becomes "put decisions in `## Decisions`; only the CLI writes `decisions.md`; no token counts in `handoff.md`", so no step is renumbered and "if step 3 failed" still points at the persist step. The always-apply rule budget (12000 characters, `test/smoke.test.js`) and the `templates/AGENTS.md` budget (4000 characters, `test/archive-from-terminal.test.js`) only get more room. The root `.agents/rules/session-handoff.mdc` is copied with `cp`, never with `init --force`.

**D9. Slicing.** The delta specs, design, tasks and proposal total well under 150000 B and `tasks.md` under 60000 B, so the change ships as one slice. Tasks are ordered: new tests that fail on the old code (1), text mirrors (2), `bin/` (3), converted tests (4), verification (5); groups 2 and 3 do not touch each other's files. Before groups 2 and 3 the new test file has 8 tests: tests 1 to 6 and 8 fail on the old code and test 7 passes (`# pass 1`, `# fail 7`; the first seven alone give `# pass 1`, `# fail 6`).

## Intentionally changed scenarios and tests

(renamed, gains the bare `Reviewer` assertions, task 4.6). Unchanged on purpose: "metrics treats legacy sessions without spendSource as unreported without rewriting the file" (it pins the readable legacy `self-report` value) and the `## Metrics` extra section in `test/restore-recovery-briefing.test.js` ("superseded checkpoint is used for decisions only").

## Risks / Trade-offs

- [Old rule text in consumer installs still asks for `## Metrics`] → harmless: the section is ignored and dropped; `update` refreshes the text.
- [Cursor sessions without a platform (5 of 61 in the plan evidence)] → unchanged: the manual `--platform` / `--model` flags stay; only the misleading hint goes.
- [Legacy `self-report` sessions lose the freeze] → D4: in the CLI leftover only; no recorded session is affected; pinned by a scenario and test 6.
- [The Cursor hook leftover (`scripts/cursor-spend-collect.cjs`, both copies) keeps freezing a stored legacy `self-report` session with numbers, so the CLI and the hook differ for that value] → accepted and documented in D4 and in the delta: the practical impact is nil (0 of 95 sessions in 20 ledgers have `self-report`), and changing the script would reopen the byte-identical template copy and `test/spend-collect.test.js` for no recorded case.
- [Mixed language inside MODIFIED blocks] → untouched text is byte-exact Ukrainian from the main spec; new sentences are English per `project.agent_language`.
- [Two changes MODIFY the same requirement and the later archive overwrites the earlier] → `openspec list` shows no other active change, and every MODIFIED block was copied from the current main spec, so no earlier archived delta is overwritten.
- [`resolveSessionSpend` signature change breaks a caller] → its only callers are `applyCollectedSessionFields` and `test/metrics-readable.test.js`, both edited here.

## Migration Plan

No data migration. Implement in the task order; revert the commit to roll back. Existing handoffs and ledgers are read as before; new persists simply stop writing the section.
